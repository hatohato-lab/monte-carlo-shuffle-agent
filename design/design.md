# monte-carlo-shuffle-agent 設計メモ

この文書は「なぜこの設計にしたか」の記録。使い方は README、専門用語を使わない入門は 説明書.md。

## 実証する設計パターン
**モンテカルロ（統計的）オラクル**。出力が毎回変わる**非決定**な処理を、1回でなく
**多数回実行した集計のふるまい**で判定する。

## なぜこの方式を選んだか（他方式との比較）★この repo の肝
- シャッフルは**正解が1つに決まらない**（毎回違う順で正しい）。だから golden（出力一致）も差分テストも使えない。
- 「正しさ」は1回の出力でなく**統計的性質**にある：毎回 並べ替えであること（妥当性）＋ 長い目で偏りなく散らばること（一様性）。
- これを測るのが**多数回実行＋統計検定（カイ二乗）**＝モンテカルロ・オラクル。種を固定して再現可能にする。
- 対比：差分テスト/golden＝正解が決まる時。メタモルフィック＝関係が言える時。LLM審査＝質が主観の時。本 repo は「**毎回ぶれるが統計に法則がある**」列を担当。

## 判定する2点
- 妥当性: 毎回、入力の並べ替え（多重集合・長さ一致）で、引数を破壊しない。重複要素・空リスト・長さ1の入力でも成り立つ。要素値を 0..K-1 以外にすることで、入力を無視して `range(K)` を返す実装も弾く。
- 一様性: 2段のカイ二乗検定。(1) 位置ごと周辺分布 — 各位置の要素出現が期待値 N/K に近い。(2) 順列全体 — 4!=24 通りの並びの度数が均等。位置ごとだけでは「各位置は均等だが出せる並びが数種類」の巡回シフト型を見逃すため、順列全体の検定で塞ぐ。閾値はカイ二乗分布の臨界値（順列は df=23・α=0.001 の≈49.73）を根拠に置く。

## なぜ信頼できるか（オラクル自己検証）
`--selftest` で、正しいシャッフルは PASS、既知バグ（混ぜない／先頭だけ交換＝偏り、1個落とす＝妥当性違反、巡回シフト＝周辺分布は通るが順列偏り）は FAIL になることを示す。

## 既知の限界
- 一様性検定は有限回・有限の閾値。微妙な偏り（例: わずかに偏った Fisher–Yates）は N と閾値の設定しだい。
- 検定は「分布が一様か」を見る。暗号的乱数性までは保証しない。
- 候補コードはサンドボックス無しで import 実行するため、信頼できないコードの採点には使わない。

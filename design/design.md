# monte-carlo-shuffle-agent 設計メモ

この文書は「なぜこの設計にしたか」の記録。使い方は README、概念入門は 01_airepo の `00_入門_…`／`00_詳説_…`。

## 実証する設計パターン
**モンテカルロ（統計的）オラクル**。出力が毎回変わる**非決定**な処理を、1回でなく
**多数回実行した集計のふるまい**で判定する。

## なぜこの方式を選んだか（他方式との比較）★この repo の肝
- シャッフルは**正解が1つに決まらない**（毎回違う順で正しい）。だから golden（出力一致）も差分テストも使えない。
- 「正しさ」は1回の出力でなく**統計的性質**にある：毎回 並べ替えであること（妥当性）＋ 長い目で各位置に各要素が均等に来ること（一様性）。
- これを測るのが**多数回実行＋統計検定（カイ二乗）**＝モンテカルロ・オラクル。種を固定して再現可能にする。
- 対比：差分テスト/golden＝正解が決まる時。メタモルフィック＝関係が言える時。LLM審査＝質が主観の時。本 repo は「**毎回ぶれるが統計に法則がある**」列を担当。

## 判定する2点
- 妥当性: 毎回、入力の並べ替え（多重集合・長さ一致）。
- 一様性: 位置ごとに、各要素の出現回数が期待値 N/K に近い（カイ二乗 < 閾値）。偏った/混ぜないシャッフルは巨大なカイ二乗で弾かれる。

## なぜ信頼できるか（オラクル自己検証）
`--selftest` で、正しいシャッフルは PASS、既知バグ（混ぜない／先頭だけ交換＝偏り、1個落とす＝妥当性違反）は FAIL になることを示す。

## 既知の限界
- 一様性検定は有限回・有限の閾値。微妙な偏りは N と閾値の設定しだい。
- 検定は「分布が一様か」を見る。暗号的乱数性までは保証しない。
